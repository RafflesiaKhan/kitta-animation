# Kitta v2 step 1: action library plan

## Task 1 — shared action library and playback

Files: `shared/types.ts`, new `shared/actions.ts`, `shared/vector-avator/kitta.ts`,
`shared/timeline.ts`, motion tests. Add the string action id type, validated action
metadata, built-in aliases for the nine legacy ids, and a loader/parser that reuses
`parseMotion` and rejects unknown bones. Make `poseFor` resolve the action by id and
implement once, loop, and hold progress without changing `lookDown`'s head pitch.

Tests: parser defaults old clips to loop, accepts all legacy ids and custom metadata,
rejects unknown bones, and verifies once/loop/hold sampling.

## Task 2 — server library and validation

Files: new `server/actions.ts`, `server/index.ts` (one route mount only),
`server/validate.ts`, `server/projects.ts`, server tests. Load bundled clips plus
`data/motions/*.json`, expose the same action records to the browser, and use library
ids for export/project validation while preserving unknown-id rejection.

Tests: route output, custom-file loading, valid custom ids, and invalid ids.

## Task 3 — Animate palette

Files: `src/steps/AnimateStep.tsx`, UI tests. Fetch/register the server library for
vector characters, show labels and needs-based disabled tooltips, and keep starter
and painted characters restricted to the nine legacy actions. Use the existing mark
editing path so preview and export continue to consume the same timeline marks.

Tests: vector custom label and add behavior, needs tooltip/disabled state, and
legacy-only starter/art palettes.

## Verification

Run `npx vitest run` and `npx tsc --noEmit -p .` before every commit. Run the
required real saved-project and temporary `data/motions` checks if the owner data is
available; remove only files created by the checks. Review each task diff, then run
the full-step review and record any unavailable live checks plainly.
