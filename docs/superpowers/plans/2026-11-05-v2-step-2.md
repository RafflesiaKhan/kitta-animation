# Kitta v2 step 2

Work on `test-cd/kitta-v2-first-scene`. Follow the shared rules and the draft comparison. Implement these tasks in order. Write and run the failing test first, run the full Vitest and TypeScript checks before each commit, and have a fresh agent review each task. Finish with a whole-step review and live acceptance.

## 1. Projects, episodes, and assets

- Add `shared/projects.ts` with `ProjectStyle`, `Project`, `Episode`, and a discriminated `ProjectAsset` for managed files and saved character references. Use stable UUIDs.
- Add `server/projects.ts` with `projectRoutes(root = resolve('data/projects'))` and mount it in `server/index.ts`. Support list/create/open, create episode, and import/fetch assets. Carry over the draft's route and validation patterns file by file. Keep updates synchronous around read/modify/write, write a unique temp file beside the JSON, and rename it. Store managed files under `media/` and preserve existing draft files. Open a style-less draft as SVG and preserve its episode data on writes.
- In `tests/server/projects.test.ts`, cover valid image/SVG/audio uploads and bytes, style validation, saved-character imports and deduplication, fresh-router reopen, isolation, bad project IDs and traversal filenames, and draft compatibility. Validate supported bytes, keep filenames display-only, and serve imported SVG with sandbox and nosniff headers.

## 2. Durable scenes

- In `server/scene.ts`, add `snapshotScene(scene)` and `hydrateScene(saved)` so saved AI actors hold IDs and resolve current metadata, including when reading legacy built snapshots. Keep preview and export on the existing `SceneView` and `renderScene`.
- Add `ProjectScene` in `shared/projects.ts` with a stable ID, managed audio/background asset IDs, and stable per-actor cue IDs alongside the accepted timing data. Extend `server/projects.ts` with episode sample save, scene read, and render/download routes. Import the built Step 1 scene into an SVG project, copy its audio/background into managed media, return a helpful CLI preparation message when missing, and make repeat saves idempotent. Preserve style-less draft records and their legacy fields.
- Test scene and cue IDs, reloading with the original source media gone, render equivalence, current AI pose metadata after a repaint, and retries without synthesis. Use fixtures and no paid API or VoiceStudio in automated tests.

## 3. Projects UI

- Reuse the draft's project forms, tabs, and picker in `src/Projects.tsx` and `src/styles.css`. Add typed project calls in `src/api.ts`, style selection, project asset and episode controls, sample save, and render/download.
- In `src/ScenePreview.tsx`, reuse the audio-clock preview for a loaded scene and its scoped audio URL. In `src/main.tsx`, make Projects the home and preserve the four-step workspace and direct `?scene` preview.
- Add `tests/ui/projects.test.tsx` for create/open, asset and scene flows, and navigation. Verify in a browser against checkout-owned listeners. Use isolated loopback ports if the default listeners belong to an existing session. Record live evidence and remaining gaps in the Step 2 report.
